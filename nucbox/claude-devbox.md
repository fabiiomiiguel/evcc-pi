# Two LXD containers: `devbox` (personal) and `dogchefbox` (dogchef)
Projects run inside LXD containers, not on this host; `~/projects` and `~/orca` are mounted there at the same paths, so files are the same on both sides, only commands differ. The host has no docker, php or composer.

- A repo is dogchef when `git remote get-url origin` contains `dogchef-be/` or it is under `~/projects/dogchef` (today: dev and its worktrees, dev-backoffice-frontend-consolidation, freshchef-ui, nuxt-ab-segment, nuxt-intercom, nuxt-maps, nuxt-prevent-multitabs, proto-dogchefapp). Its stack (dev-apps, dev-mysql, dev-proxy, ...) runs in the LXD container `dev`: prefix every `make`, `docker`/`docker compose`, `npm`/`npx`/`node`, `composer`/`php`, test and `.claude/scripts/*.sh` command with `dogchefbox`, e.g. `dogchefbox make start`, `dogchefbox docker exec dev-apps ...`. `https://<app>.test` only resolves inside: `dogchefbox curl -sk https://<app>.test/...`; `preview_start` cannot reach it, serve with `/test` and check with dogchefbox curl. The dev DB goes through Cloudflare WARP inside (`lxc exec dev -- warp-cli --accept-tos status`); if `make reset-db-*` cannot connect, report it, registration needs the user's login. After a reboot the stack is down: `cd ~/projects/dogchef/dev && dogchefbox make start`.
- Every other code repo (~/projects/personal, ~/projects/oss, ~/projects/ffv0 and Orca worktrees of them) runs in the LXD container `personal`: the same command prefix is `devbox` (`devbox make up`, `devbox corepack pnpm test`, `devbox composer check`, `devbox .venv/bin/python ...`). A dev server inside is reachable on the host's 127.0.0.1 only through an LXD proxy device (README "Personal projects in LXD"); without one, check it with `devbox curl`.
- Exceptions that run on the host, no prefix: evcc-pi (its nucbox scripts manage this host; tests `node --test nucbox/tests`), factory (Claude Code plugin), ffv0/slack (Everon: `make app`, `npm --prefix electron test`), ffv0/ai, ffv0/dagu.
- Both prefixes keep the current directory and run as fabio with the docker group; compound commands: `devbox bash -c '...'`. Each refuses the other's folders (exit 2 with the right name); never work around it with `lxc exec` by hand.
- `git commit` and anything that fires git hooks runs through the repo's prefix (the hooks need the container's tools); read-only git (status, diff, log, fetch) is fine on the host.
- Never start a project's stack with the host's own tools, and never install a project's dependencies on the host.
